# AI Orchestration Dedup — Merge Summary

## What changed
- `dm_brain.py` is now the single source of truth for AI/DM orchestration.
- `ai_director.py` is deleted.

## Why dm_brain.py, not ai_director.py
`dm_brain.py`'s `update_dm_brain()` is the function `main.py` actually
calls every game-loop tick. `ai_director.py`'s equivalent dispatcher,
`direct_gameplay()`, was never called anywhere in the codebase — the
only thing imported from `ai_director.py` was `change_tension`, and
even that was imported but never invoked in the pre-merge `dm_brain.py`.

## What was merged in from ai_director.py
- `recent_battles` / `recent_story_events` counters → added to `dm_state`
- `evaluate_session_flow()` → merged as-is (still not called by anything, same as before)
- `evaluate_campaign_pressure()` → merged as-is (still not called by anything, same as before)
- `reset_session_trackers()` → merged as-is
- `show_director_state()` → merged, renamed `show_dm_state()`
- Event handlers for `narrative_encounter` and `quest_completed` → merged
  (dm_brain.py did not previously subscribe to these; ai_director.py did)

## What was dropped, and why
- `direct_gameplay()` — functionally duplicated `update_dm_brain()`
  (same three-phase dispatch, same generator calls). Never called by
  anything. Carrying it forward would just be two copies of the same
  logic in one file, so it was not merged.
- `director_state["tension"]` as a separate value — nothing outside
  `ai_director.py` ever read it. Replaced by the single
  `dm_state["story_pressure"]`, which is what actually drives
  `update_dm_brain()`.
- The unused `from ai_director import change_tension` line in the old
  `dm_brain.py` — dead import, never called.

## Behavior impact
No gameplay behavior changes. The functions merged in were dormant
before (not called by `main.py`) and remain dormant after — they're
preserved as available functions for future wiring, not activated.

The one technical (not gameplay-visible) change: `enemy_killed` and
`world_collapse` were each previously handled by two independent
subscribers tracking two disconnected numbers (`story_pressure` in
dm_brain.py, `tension` in ai_director.py — only the former ever
affected anything). Now each event is handled once, by the number that
was actually driving behavior. Net game-visible effect: none.

## Imports to update elsewhere
None found. No file other than the old `dm_brain.py` imported from
`ai_director.py` in the 8 files I reviewed directly (dm_brain,
memory_engine, world_state, quest_generator, consistency_engine,
llm_bridge, ai_director, faction_manager) or in `main.py`.

**Caveat:** I have not read every file in the repo (e.g.

`region_manager.py`, `session_manager.py`, `save_system.py`,

## How to apply
```bash
cd /path/to/ai-rpg-engine
git rm ai_director.py
cp /path/to/downloaded/dm_brain.py ./dm_brain.py
git add dm_brain.py
git commit -m "Merge ai_director.py into dm_brain.py; establish single AI orchestration path

- dm_brain.py is now the sole AI/DM orchestration module (main.py already
  called its update_dm_brain() exclusively; ai_director.py's direct_gameplay()
  was dead code, never invoked).
- Merged non-dead ai_director.py functionality into dm_brain.py:
  evaluate_session_flow(), evaluate_campaign_pressure(),
  reset_session_trackers(), show_director_state() (renamed show_dm_state()),
  and event handlers for narrative_encounter / quest_completed.
- Unified the two parallel tension trackers (dm_state.story_pressure vs.
  director_state.tension) into a single dm_state[\"story_pressure\"], since
  only story_pressure ever drove actual gameplay dispatch.
- Removed direct_gameplay() as a pure duplicate of update_dm_brain(); removed
  dead import of change_tension from the old dm_brain.py.
- Deleted ai_director.py.
- No gameplay behavior changes: all merged functions were uncalled before
  this commit and remain uncalled after it, preserved for future wiring."
git push
```
